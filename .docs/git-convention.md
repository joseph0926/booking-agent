# Git 규칙

이 저장소의 커밋과 반영 방식이다. git-suggest 스킬과 에이전트는 이 파일을 우선한다. 학습 진행과 판정은 study 저장소의 [서버와 AI 애플리케이션 트랙](../../study/engineering/tracks/backend-ai/README.md)이 소유하고, 커밋은 그 과정을 코드로 남긴다.

## 흐름

- 브랜치를 만들지 않는다. `main`에서 커밋하고 `origin/main`에 바로 push한다.
- PR을 만들지 않는다. 그래서 브랜치명과 PR 본문은 추천하지 않는다.
- 명령은 제안만 하며 직접 실행하지 않는다. 커밋마다 포함할 경로를 명시한 `git add`와 `git commit -m`을 한 묶음으로 제안한다.

## 커밋 나누기

- 실패하는 테스트와 그 테스트를 통과시키는 구현은 다른 커밋으로 나눈다. 테스트 커밋이 먼저 온다.
- 한 번에 여러 커밋을 제안할 때는 작업한 순서대로 나열한다. 순서는 학습 로그의 기록 순서로 확인한다.
- 뼈대, 설정, 반복 코드 같은 준비 변경은 그 주 원리를 구현한 코드와 다른 커밋으로 나눈다.
- 의존성 변경(`package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`)은 그 의존성을 처음 쓰는 커밋에 함께 넣는다.
- `git add -p`(`--patch`)처럼 파일의 일부만 골라 담는 명령은 제안하지 않는다. 커밋은 파일 단위로 나눈다.

## 커밋 메시지

- 제목: `<타입>: <요약>` 한 줄로 쓴다. 타입은 `feat`, `fix`, `test`, `refactor`, `docs`, `chore` 중 변경에 맞는 것을 고른다. 요약은 한국어로 쓰고 추가, 수정, 연결처럼 변경을 나타내는 명사로 끝낸다. 타입을 포함해 72자 이내이며 마침표를 붙이지 않는다.
- 본문: 쓰지 않는다. 제목 한 줄로 끝낸다.
- AI 도구나 모델 사용을 드러내는 문구와 trailer(`Co-Authored-By`로 AI를 표기하는 것 포함)를 넣지 않는다.

예:

```
test: 같은 시간대 예약 요청의 실패 테스트 추가
```

```
feat: 예약 이름과 시작 시각의 잘못된 입력 거절
```
